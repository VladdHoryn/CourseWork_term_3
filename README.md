# 🏥 Система для автоматизації роботи з даними стоматологічної клініки (Clinic Management System)

Повнофункціональний кросплатформовий веб-додаток корпоративного рівня, розроблений на базі **ASP.NET Core (.NET 9.0)** та **MongoDB**, що автоматизує процеси взаємодії між пацієнтами, медичним персоналом, операторами та адміністрацією клініки.

Проєкт реалізує сучасну багатошарову архітектуру, надійну рольову модель доступу (RBAC) за допомогою JWT-токенів, безпечне хешування паролів та унікальну систему аналітичного опрацювання даних (інтерпретатор SQL-запитів у MongoDB-команди).

## 💎 Бізнес-цінність проєкту

Впровадження даної системи розв'язує критичні проблеми традиційного менеджменту в медичних закладах, перетворюючи хаотичні потоки паперів та дзвінків на структуровану цифрову екосистему.

* **Для клініки (Оптимізація та доходи):** Автоматичний контроль завантаженості лікарів мінімізує простій кабінетів. Інтегрована система виставлення рахунків забезпечує прозорий облік фінансів, а логування дій персоналу унеможливлює внутрішні зловживання.
* **Для медичного персоналу (Ефективність):** Лікарі мають персоналізовані цифрові кабінети з актуальним розкладом візитів, миттєвим доступом до скарг пацієнтів та можливістю виписування медичних призначень в один клік.
* **Для пацієнтів (Сервіс вищої якості):** Зручний інтерфейс для самостійного запису на прийом, прозорий моніторинг статусу оплати та надійна автентифікація, яка гарантує повну конфіденційність персональних та медичних даних.

## 💻 Технологічний стек

### Бекенд (Backend)
* **Платформа:** .NET 9.0 (Сучасна, швидка кросплатформова середа виконання).
* **Веб-фреймворк:** ASP.NET Core Web API / MVC (Гнучке налаштування конвеєра обробки HTTP-запитів).
* **База даних:** MongoDB (Високопродуктивна NoSQL БД для гнучкого збереження неструктурованих медичних карток).
* **Драйвер БД:** `MongoDB.Driver` версії 3.5.0.
* **Безпека та автентифікація:** * JWT (JSON Web Tokens) на базі `Microsoft.AspNetCore.Authentication.JwtBearer` (версія 9.0.10).
  * `BCrypt.Net-Next` версії 4.0.3 для надійного асиметричного криптографічного хешування паролів із додаванням солі.

### Фронтенд (Frontend)
* **Технології:** HTML5, CSS3 (Сучасна семантична верстка).
* **Стилізація:** Bootstrap (Адаптивний дизайн під мобільні пристрої та ПК).
* **Клієнтська логіка:** Vanilla JavaScript (Модульна структура, асинхронні запити Fetch API, динамічний рендеринг сторінок на основі JWT-claims).

## 👥 Рольова модель та функціонал

В системі реалізовано суворе розмежування прав доступу на рівні контролерів (Authorization Policies). Кожна роль має свій ізольований користувацький інтерфейс:

### 1. Гість (Guest)
Початкова точка входу в систему.
* Ознайомлення з переліком доступних послуг клініки.
* Перегляд списку практикуючих спеціалістів та їхнього профілю.
* Подача електронної заявки на реєстрацію (Registration Request) із внесенням первинних даних.

### 2. Пацієнт (Patient)
Зареєстрований користувач, що отримує медичні послуги.
* Перегляд власного кабінету та історії медичних візитів.
* Створення нових заявок на прийом до конкретного лікаря на вибраний час.
* Моніторинг виставлених рахунків та здійснення онлайн-оплати візитів.

### 3. Спеціаліст / Лікар (Specialist)
Професійний медичний працівник.
* Перегляд особистого розкладу прийомів у реальному часі.
* Фіксація скарг пацієнта, внесення анамнезу та медичних призначень під час візиту.
* Зміна статусів візитів (наприклад, завершення прийому).

### 4. Оператор (Operator)
Менеджер реєстратури та фінансового обліку.
* Верифікація та затвердження/відхилення запитів на реєстрацію від нових гостей.
* Керування базою пацієнтів та спеціалістів.
* Валідація платежів та контроль фінансових надходжень за медичні послуги.

### 5. Адміністратор (Administrator)
Повний контроль над системою та даними.
* Керування обліковими записами всіх користувачів, створення профілів операторів та лікарів.
* Перегляд системних аудит-логів (Audit Logs) для моніторингу безпеки та дій користувачів.
* **Унікальний аналітичний інструмент:** Виконання низькорівневих аналітичних запитів до MongoDB за допомогою синтаксису SQL або сирого JSON.

## 🏗 Архітектура та компоненти системи

Проєкт спроєктований за патерном **Repository-Service-Controller**, що забезпечує чітке розділення відповідальності (Separation of Concerns):

1. **DataAccess / Repositories:** Безпосередньо взаємодіють з колекціями MongoDB. Використовують типізовані контексти (`IMongoCollection<T>`). Включають спеціалізовані класи для кожної сутності (наприклад, `UserRepository`, `VisitRepository`, `PaymentRepository`).
2. **Business Logic / Services:** Містять бізнес-правила системи. Обробляють дані, отримані з репозиторіїв, перевіряють бізнес-обмеження, взаємодіють із `PasswordHasher` та генерують винятки, якщо правила порушено (наприклад, `UserService`, `VisitService`).
3. **Presentation / Controllers:** Складають REST API проєкту. Приймають вхідні DTO (Data Transfer Objects), забезпечують маршрутизацію (`api/[controller]`) та повертають уніфіковані HTTP-відповіді (`Ok`, `Unauthorized`, `BadRequest`).

## 🚀 Інструкція із розгортання та запуску

### Попередні вимоги
1. Встановлений **.NET 9.0 SDK**.
2. Запущений локальний або хмарний екземпляр **MongoDB** (за замовчуванням очікується на порту `27017`).

### Кроки для запуску
1. Клонуйте репозиторій із кодом проєкту.
2. Перейдіть до кореневої директорії з файлом `CourseWork.sln` або файлом проєкту `CourseWork.csproj`.
3. Перевірте конфігурацію підключення у файлі `appsettings.json`:
   ```json
   "MongoDbSettings": {
     "ConnectionString": "mongodb://localhost:27017",
     "DatabaseName": "CourseworkDB"
   },
   "Jwt": {
     "Key": "SuperSecretKeyThatShouldBeLongAndSecure"
   }
